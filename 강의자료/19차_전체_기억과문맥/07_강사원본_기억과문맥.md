## §A. 원본 그림과 트리

### A-1. 머리 해부도 (슬라이드 08·09 — 수강생용은 상자 그림, 이름만)

```
┌──────────── 소재 일꾼의 머리 (지금 이 순간) ────────────┐
│ ① 지침 한 장            ← 작업대가 읽어 준다 (늘)         │
│ ② 이번 요청문 + 경로     ← 지휘자가 넣는다 (이번에)        │
│ ③ 손으로 읽은 파일       ← 일꾼이 스스로 (읽는 순간부터)    │
│ ④ 손을 쓴 결과·에러      ← 작업대가 돌려준다 (쓸 때마다)    │
└──────────────────────────────────────────────────────┘
   밖(선이 없다):  ⑤ 내 대화   ⑥ 다른 일꾼이 한 일   ⑦ 어제 처리한 건   ⑧ 폴더에 있지만 안 읽은 파일
```
슬라이드 10은 같은 상자에 **눈금**을 그려 "넣을수록 자리가 준다 → 넘치면 ①이 밀려 나간다"를 보인다.

### A-2. 해부도 트리 (슬라이드 26 — 18차 트리 + 자료/)
```
접수-에이전트/
  CLAUDE.md                 ← 1층 늘 드는 것 (지휘자 규칙 + 보내는 표)
  일꾼/
    소재.md · 성과.md · 일정.md   ← 1층 늘 드는 것 (일꾼 지침 한 장)
  자료/                      ← 4층 찾아 꺼내는 것 (브랜드.md · 규정집.md · 지난사례/)
  inbox/                     ← 2층 이번에 넣는 것 (요청문)
  runs/                      ← 3층 하다가 남긴 것 (상태 · 결과)
```
화살표 셋(머리로 들어가는 길): **늘** = 작업대가 / **넘겨서** = 지휘자가 / **꺼내서** = 일꾼이 손으로.

### A-3. 작업대(Claude Code) 실제 대응표 (강사만 — 슬라이드에 없음)

| 오늘의 이름 | 작업대에서의 실물 | 비고 |
|---|---|---|
| ① 지침 한 장 (1층) | 일꾼 정의 파일 `.claude/agents/<이름>.md`의 본문 = 그 일꾼의 **시스템 프롬프트** | 일꾼은 이 글을 **늘** 든다. 부모 세션의 시스템 프롬프트와는 별개 |
| 전체 규칙 (1층) | `CLAUDE.md` (루트·상위 폴더·사용자 홈의 계층) | **서브에이전트에 전달되는지는 리허설 §F-5에서 직접 확인.** 어느 쪽이든 설계 원칙은 같다 — "일꾼이 알아야 할 규칙은 일꾼 지침에 적는다, 전체 규칙에 기대지 않는다" |
| ② 이번 요청문 + 경로 (2층) | 부모가 서브에이전트를 부를 때 넘기는 **요청문(프롬프트)** | 부모의 대화·부모가 읽은 파일은 **안 넘어간다.** 필요한 건 요청문에 적거나 파일 경로를 적는다 |
| ③ 손으로 읽은 파일 | 일꾼이 Read 도구로 연 파일의 내용이 일꾼 문맥에 들어간 것 | 큰 파일을 열면 그만큼 자리를 먹는다(과식의 셋째 원인) |
| ④ 손을 쓴 결과 | 도구 호출의 반환값(실행 출력·에러·검색 결과) | 긴 출력도 전부 문맥에 쌓인다 — B-10 |
| ⑤ 내 대화 (안 든 것) | 부모 세션의 메시지 이력 | 18차 Q4·오늘 Q0의 실물 |
| ⑥ 다른 일꾼이 한 일 (안 든 것) | 다른 서브에이전트의 문맥 | 부모에겐 각 일꾼의 **최종 결과(요약)만** 돌아온다. 일꾼끼리는 아무것도 공유하지 않는다 |
| ⑦ 어제 처리한 건 (안 든 것) | 끝난 세션·끝난 서브에이전트 호출의 문맥 | 세션이 끝나면 사라진다. 남는 건 파일뿐 |
| ⑧ 안 읽은 파일 (안 든 것) | 폴더에 있으나 Read 되지 않은 파일 | "폴더에 있다 ≠ 안다" |
| 3층 runs/ | 일꾼·지휘자가 Write로 남긴 파일 | CLAUDE.md 규칙으로 "단계마다 runs/에 한 줄"을 **명시**해야 남는다 |
| 4층 자료/ | 폴더의 참고 파일 | 일꾼 지침에 "○○일 때 자료/규정집.md의 '○○' 항목을 읽는다"가 있어야 읽는다. 전체를 읽으라고 하면 과식 |
| 머리의 크기 | 모델의 컨텍스트 창(토큰 수) | B-1 |
| 요약·압축 | 긴 세션에서 작업대가 앞부분을 요약해 자리를 만드는 것 | B-6 — "앞을 잊는다"의 실물 |

### A-4. 리허설용 파일 (강사만 — 수강생에게 띄우지 않는다)

**CLAUDE.md** — 18차 §A-4 그대로 + 3층·4층 규칙 두 줄:
```
## 규칙 (얇게 — 순서·상태·호출만)
- 직접 처리하지 않는다. 반드시 아래 표대로 담당에게 보낸다.
- 일꾼을 부를 때는 요청 원문과 "참고할 파일 경로"만 넘긴다. 내 대화 내용은 넘어가지 않는다 — 필요한 건 요청문에 적는다.
- 한 단계 끝날 때마다 runs/<날짜_요청>/에 한 줄: 담당 · 읽은 것 · 낸 것.
- 두 일꾼을 거쳐야 하면 앞 일꾼의 결과 파일 경로를 뒤 일꾼의 요청문에 적는다. 내용을 복사해 넣지 않는다.
```

**일꾼/소재.md** (1층 — 열 줄 안):
```
# 소재 일꾼
- 맡는 일: 광고 소재 초안 3개를 만든다.
- 늘 지킬 것: 브랜드 톤은 자료/브랜드.md를 따른다. 요청마다 그 파일의 "톤" 항목만 읽는다.
- 받는 것: 요청 원문 + (있으면) 참고 파일 경로. 경로가 있으면 그 파일만 읽는다. 폴더의 다른 파일은 열지 않는다.
- 내는 것: 초안 3개 / 참고한 파일 이름 / 확신도(상·중·하) / 미처리 사항.
- 끝나면: runs/에 "읽은 것: …, 낸 것: …" 한 줄.
- 모르면: 지어내지 말고 "확인 필요"로 적는다.
```

**자료/** — `브랜드.md`(톤·금지어·색 — 20줄) · `지난사례/`(소재 200개를 흉내 낸 txt 200개 — 과식 장면용, 생성기로 만든다) · `성과표.csv`(200행).

## §B. 깊이 설명 전문 (러닝시트 📌 "깊이(강사용)"의 원문 — 질문이 나오면 한 줄로 답하고 슬라이드로 복귀)

### B-1. 컨텍스트 창과 토큰 (슬라이드 10)
머리의 크기는 **토큰** 수로 정해진다(한국어는 글자 1~2개가 토큰 1개 정도). 모델마다 창의 크기가 다르고, 창이 커도 비용과 지연은 넣은 양에 비례한다. 창을 다 채우면 ① 넘치는 부분이 잘리거나 ② 작업대가 앞부분을 요약해 자리를 만든다(B-6). 한 줄: "머리가 크다고 다 넣는 건, 큰 책상에 서류를 다 펼치는 것 — 찾는 데 더 오래 걸린다."

### B-2. 긴 문맥의 중간을 놓친다 (슬라이드 10·19)
모델은 긴 문맥에서 **앞부분과 뒷부분은 잘 보고 중간은 놓치는** 경향이 있다(연구에서 반복 확인된 현상, "lost in the middle"로 불린다). 그래서 "가득 차면 중간을 놓친다"고 가르친다. 실무 함의: 중요한 것은 앞(지침)이나 뒤(요청문 끝)에, 그리고 애초에 적게 넣는다.

### B-3. 머리에 든 것 넷의 실물 (슬라이드 08)
실제 문맥은 ① 시스템 프롬프트(일꾼 지침 + 작업대가 붙이는 기본 지침) ② 메시지(요청문) ③ 도구 결과(파일 내용·실행 출력) ④ 모델 자신이 낸 말의 누적, 이렇게 쌓인다. 오늘 "든 것 넷"은 이것을 비코더용으로 다시 자른 것 — ③④가 도구 결과, 모델의 중간 말은 생략.

### B-4. 작업대의 지침 계층과 일꾼 (슬라이드 13)
작업대는 지침을 **계층**으로 읽는다 — 사용자 홈의 CLAUDE.md, 프로젝트 루트의 CLAUDE.md, 하위 폴더의 CLAUDE.md. 일꾼(서브에이전트)은 자기 정의 파일의 본문을 시스템 프롬프트로 든다. **프로젝트 CLAUDE.md가 일꾼에게도 전달되는지는 작업대 버전에 따라 다를 수 있다 — 리허설 §F-5에서 직접 확인하고 슬라이드 13 멘트를 그에 맞춘다.** 어느 쪽이든 가르칠 원칙은 하나: **일꾼이 알아야 할 규칙은 일꾼 지침에 적는다. 전체 규칙에 기대지 않는다.** (전달되더라도 전체 규칙은 지휘자용이라 일꾼에겐 소음이 된다 — 1층을 짧게 유지하는 이유.)

### B-5. 서브에이전트의 문맥 분리 (슬라이드 07·09 — 18차 B-10 재수록)
작업대의 서브에이전트는 **별도 문맥**에서 실행되고, 부모 세션에는 최종 결과(요약)만 돌아온다. 부모의 대화·부모가 읽은 파일은 전달되지 않으므로 필요한 정보는 **요청문에 명시하거나 파일 경로를 넘겨야** 한다. 이 분리가 비용·안정성의 이유이자 "각자 머리를 작게"의 실물. 강사는 수업 전 직접 확인(§F-4).

### B-6. 요약·압축 (슬라이드 10·18)
세션이 길어져 창이 차면 작업대가 **앞부분을 요약**해 자리를 만든다(자동 압축). 요약은 손실이 있다 — 그래서 "앞을 잊은 것처럼" 행동한다. 긴 일은 한 세션에 다 넣지 말고 runs/에 상태를 남기고 끊어 가는 것이 3층의 이유.

### B-7. 검색 증강(RAG)과 의미 검색 (슬라이드 16)
4층 "찾아 꺼내기"의 자동판. 질문을 받으면 자료 더미에서 **관련 조각**만 찾아(의미 검색 — 18차 B-5) 문맥에 넣어 준다. 오늘은 "일꾼이 지침대로 손으로 해당 항목을 읽는다"까지만 — 자료가 수십 쪽을 넘으면 RAG가 필요해진다. 한 줄: "서랍이 커지면 찾아 주는 사서를 둔다 — 그게 RAG."

### B-8. 메모리 파일 · 장기 기억 (슬라이드 15·16, 부록 31)
"기억"이라는 이름이 붙은 기능들(메모리, 프로젝트 지식 등)의 실체는 **파일에 적어 두고 다음에 다시 읽는 것**이다. 일꾼 자체는 기억하지 않는다 — 머리는 매번 비어서 태어난다. 그래서 "일꾼이 기억하게 할 수 없나요?"의 답은 "파일이 곧 기억입니다 — 3층·4층". 무엇을 적을지(상태 vs 사례)와 언제 읽을지(늘 vs 꺼내서)를 정하는 것이 설계.

### B-9. 프롬프트 캐싱 (슬라이드 13)
문맥의 **앞부분이 매번 같으면** 그 부분의 처리 결과를 재사용해 비용·지연을 줄이는 기능. 1층(지침)이 짧고 **고정**이어야 하는 둘째 이유 — 매번 바뀌는 내용을 지침에 섞으면 캐시가 깨진다. 한 줄: "늘 드는 것은 앞에, 그리고 안 바뀌게."

### B-10. 도구 결과가 머리를 먹는다 (슬라이드 19·21)
파일을 열면 파일 전체가, 명령을 실행하면 출력 전체가 문맥에 들어온다. 큰 CSV 한 번, 긴 로그 한 번이면 머리가 찬다 — 과식의 셋째 원인(폴더 통째·대화 전체 다음). 처방은 넘기기(경로만)와 꺼내기(해당 항목만)이고, 지침에 "파일은 필요한 부분만 읽는다"를 적는다.

### B-11. 문맥 오염 (슬라이드 18)
틀린 것이 문맥에 들어가면 모델은 그것을 **참으로 놓고** 일한다 — 낡은 규정, 다른 요청의 결과, 지난 바퀴에서 반려된 초안, 심지어 자료 안에 적힌 "지시문"(외부 문서에 섞인 명령). 처방: 넣기 전에 거른다(가드레일의 입력 쪽), 지난 바퀴의 틀린 것은 넘기지 않는다(넣는 법 ④), 자료는 내용이지 지시가 아니라고 지침에 적는다.

### B-12. 창이 커지면 해결되나 (부록 31 FAQ 1)
창이 커져도 ① 중간 놓침(B-2)은 남고 ② 비용·지연은 넣은 양에 비례하며 ③ 관련 없는 것이 많을수록 판단이 흐려진다. 창의 크기는 "넣을 수 있는 양"이지 "넣어야 할 양"이 아니다. 한 줄: "크기가 아니라 **무엇을** 넣나."

## §E. FAQ 10

1. **"그냥 다 넣고 큰 모델 쓰면 안 되나요?"** — 창이 커도 중간을 놓치고, 넣은 만큼 느리고 비싸고, 관련 없는 게 많을수록 흐려진다. 크기가 아니라 **무엇을** 넣나(B-12).
2. **"일꾼이 기억하게 할 수는 없나요?"** — 파일이 곧 기억이다. 상태는 runs/(3층), 사례는 자료/(4층). "기억" 기능들의 실체도 파일(B-8).
3. **"지침이 자꾸 길어지는데요?"** — 열 줄 넘으면 신호. 늘 필요한 것만 남기고 나머지는 4층으로 내려보낸다 — "○○일 때 자료/○○의 해당 항목을 읽는다" 한 줄로.
4. **"Claude Code가 알아서 다 넣어 주는 거 아니에요?"** — 작업대가 넣는 건 1층(지침)과 ④(손의 결과)뿐. 2층(받는 것)·3층(상태)·4층(꺼낼 것)은 설계하는 사람 몫(슬라이드 12 표).
5. **"폴더에 있으면 알아서 읽지 않나요?"** — 아니다. 읽은 것만 안다. 지침에 "언제 무엇을 읽는다"가 있어야 읽고, 없으면 옆에 두고도 모른다(Q2).
6. **"같은 일꾼이 두 번째 바퀴 돌면 첫 바퀴를 알지 않나요?"** — 한 번 부른 안에서는 남지만, 호출이 끝나면 사라진다. 바퀴 사이에 남는 건 파일뿐(Q3).
7. **"파일 경로만 넘기면 안 읽으면 어떡해요?"** — 지침에 "경로가 있으면 그 파일을 읽는다"를 적는다. 넘기기(경로)는 꺼내기(지침) 와 짝이다.
8. **"그럼 대화창에서 말로 한 건 전부 소용없어요?"** — 지휘자(부모)는 안다. 일꾼은 모른다. 일꾼에게 가야 할 말은 받는 것에 적는다(Q0).
9. **"RAG를 쓰면 되지 않나요?"** — 자료가 커지면 그렇다. 오늘은 손으로 꺼내기까지. RAG는 4층의 자동판(B-7).
10. **"실제로 돌려 보여 주세요."** — 다음 회차(기록을 읽는 날)가 그날. 오늘은 이름 없이 돌리면 뭐가 잘못됐는지 모른다. (원칙 1 — 현재형 금지)

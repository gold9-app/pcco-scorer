6. **강사는 묻기만 한다**(실습 순회). "기타는 어디로 가요?" "이 둘은 겹치지 않아요?" "관제탑이 일을 하고 있네요?" — 답을 대신 쓰지 않는다.

## 2. 왜 이 강의인가

### 2-1. 에이전트를 "만든다"는 말의 실체
Claude Code를 써 본 사람은 이미 에이전트를 돌려 봤다 — 시키면 파일을 읽고, 고치고, 실행하고, 에러를 보고 다시 한다. 그런데 "내 업무용 에이전트를 만들어 보라"고 하면 멈춘다. 뭘 써야 하는지 모르기 때문이다. 만드는 건 코드가 아니다. **들어오는 요청을 어디로 보낼지(라우팅)와 여럿을 어떤 순서로 잇고 누가 책임질지(오케스트레이션)를 글로 쓰는 일**이다. 이 워크숍은 그 두 가지 글을 쓰는 법을 바닥부터 가르치고, 마지막에 실제로 써서 돌려 본다.

### 2-2. 왜 공항인가
라우팅과 오케스트레이션은 추상어다. 공항은 둘을 **한 장면 안에** 가지고 있다 — 게이트 배정(라우팅)과 관제탑(오케스트레이션)이 같은 건물에서, 같은 비행기를 두고, 다른 일을 한다. 그리고 관제탑은 비행기를 직접 몰지 않는다(얇은 지휘자), 비행계획서가 없으면 이륙할 수 없다(계약), 회항 절차가 미리 적혀 있다(실패 각본), 블랙박스가 있다(기록). 설계에서 빠뜨리기 쉬운 것들이 공항에선 전부 **당연한 절차**라서, "왜 그게 필요하냐"를 설명하는 대신 "공항은 왜 그렇게 하냐"를 물으면 된다.

### 2-3. 왜 자연어에 서식을 입히나
자유롭게 쓴 설계는 돌릴 수 없고, 코드로 쓴 설계는 이 대상이 못 쓴다. 중간이 필요하다 — **번호 매긴 문장, 정해진 칸, 예약어 셋(동시에 · 통과할 때까지 · 사람 확인 후)**. 이 서식은 그대로 CLAUDE.md의 "보내는 표"와 "지휘 규칙", 일꾼 파일의 지침이 된다. 설계도 4장을 쓰면 옮기기는 복사다.

### 2-4. 왜 실습을 마지막에 몰아서 하나
라우팅만 배우고 실습하면 지휘 없이 보내기만 하는 반쪽을 만들고, 오케스트레이션만 배우고 실습하면 보내는 표 없이 줄만 세운다. 둘이 한 설계도 안에서 만나야 하고, 실패 각본과 기록까지 있어야 "돈다". 그래서 전부 배운 뒤 한 번에, 대신 110분.

## 4. 모듈별 내용

### 모듈 0 — 오리엔테이션 (15분)
오늘 만드는 것 = **설계도 4장** 실물을 먼저 보여준다(완성 예시 A, 넘기기만). "이 4장을 오늘 끝에 여러분이 쓰고, 작업대에 올리고, 요청 12건을 넣어 돌립니다." 전제 없음 선언. 공항 대응표(§3) 한 장. 진행 형식(순강의 → 실습 한 번 · 손들기 6 · 생각 멈춤 4).

### 모듈 1 — 에이전트 한 대 (40분)
- **LLM**: 글을 받아 판단해 글을 낸다. 손이 없다 — 말만 한다. 한 번 답하면 끝.
- **도구(손)**: 읽기·쓰기·실행. Claude Code 화면에서 매번 보던 "읽는 중 · 실행하는 중".
- **루프**: 결과를 보고 다음 행동을 스스로 정한다 — 에러도 결과. "됐다"에서 빠져나온다. 루프에도 멈추는 규칙이 있다(상한·예산).
- **정의**: 목표를 받고, 손을 써서, 결과를 보고, 다음 행동을 스스로 정하는 AI. 4부품 머리·손·규칙·루프. **작업대(Claude Code)는 머리·손·루프를 빌려 주고, 규칙·일꾼·보내는 표·남기는 곳이 설계하는 사람의 몫.**
- **한 대의 한계 넷**: 담는 양(컨텍스트) · 규칙 충돌 · 긴 일에서 뒤로 갈수록 흐려짐 · 어디서 틀렸는지 모름 → **나눈다**(일꾼 한 명 = 한 가지 일 = 지침 한 장).
- **나누면 생기는 두 문제**: 누구에게 보내나(라우팅) · 어떤 순서로 잇고 누가 책임지나(오케스트레이션). 공항에서 — 게이트 배정과 관제탑.
- 손들기 Q1 "Claude Code 대화창에 다 시키면 안 되나요?"(토론 2분) · 생각 멈춤 ① "내 일에서 한 대로 시켰다가 흐려진 경험 하나".

### 모듈 2 — 라우팅: 누구에게 보내나 (70분)
- **정의**: 들어온 것을 보고 어디로 보낼지 정하는 일. 게이트 배정은 비행기를 몰지 않는다 — **보기만 하고 보낸다.**
- **라우팅 5층** (어디서 일어나나)
  | 층 | 무엇을 | 어디로 | 공항 |
  |---|---|---|---|
  | ① | 요청 | 담당 일꾼 | 게이트 배정 |
  | ② | 같은 종류 안의 의도 | 세부 절차 (예: 소재 요청 → 신규 / 수정) | 국내선·국제선 |
  | ③ | 이번 행동 | 어느 도구(읽기·쓰기·실행) | 활주로·유도로 |
  | ④ | 난이도 | 어느 모델(작은 머리·큰 머리 — 비용) | 소형기·대형기 |
  | ⑤ | 못 하는 것 | 사람(에스컬레이션) | 관제 승인 |
- **분류 체계 설계 3원칙**: **겹치지 않게**(한 요청이 두 종류에 동시에 맞으면 표가 틀린 것) · **빠짐없이**(올 수 있는 요청을 다 덮게) · **그리고 기타**(덮지 못한 것의 기본 경로 — 끝은 사람). "기타가 없는 분류표는 분류표가 아니다."
- **분류 기준 문장 쓰는 법 — 정·포·제·예**: 정의(이 종류란 ○○를 해 달라는 것) · 포함(이것도 이 종류: …) · 제외(이건 아님: … → 다른 종류) · 예시(실제 문장 2개). 키워드 하나로 가르지 않는다. 제외 칸이 겹침을 없앤다.
- **보내는 방식 3**: 규칙(형식·키워드 — 싸고 예측 가능, 융통성 없음) / 분류 AI(한 줄 판단 — 융통성, 불확실) / 과거 사례 매칭(쌓여야 됨). 실무는 규칙으로 거르고 남은 것을 AI가.
- **판단 재료 4**: 확신도(애매하면 사람) · 위험(돈·밖·비가역이면 사람) · 비용(큰 머리는 필요할 때만) · 시간(급하면 짧은 길).
- **애매함 처리 3**: **되묻기**(한 번만, 질문 한 개) / **추정**(가장 흔한 쪽으로 보내되 기록에 "추정" 표시) / **쪼개기**(섞인 요청은 둘로 나눠 둘 다 보낸다 — 순서는 지휘 대본이 정한다). 언제 뭘 쓰나: 되돌릴 수 있으면 추정, 아니면 되묻기.
- **재라우팅·핸드오프**: 일꾼이 "내 일 아님"을 돌려보낼 길. 일꾼 카드의 마지막 칸.
- **가드레일**(보안검색): 들어올 때 거르는 것(위험·개인정보·범위 밖) — 분류 전에 한 번.
- **안티패턴 4**: 라우터가 일을 한다 / 종류가 너무 많다(7개 넘으면 2층으로) / 기타가 없다 / 키워드만 본다.
- 손들기 Q2 "요청 종류가 몇 개면 적당할까요?"(3~7) · Q3 "'급해요'는 종류인가요?"(아니오 — 판단 재료 '시간') · 생각 멈춤 ② "내 일에 오는 요청 종류 3개 + 기타는 누구에게".

### ☕ 휴식 (10분) — (분할 시 여기서 1회 종료)

### 모듈 3 — 오케스트레이션: 어떻게 잇나 (80분)
- **정의**: 일꾼과 단계를 **순서·상태·호출**로 잇고 책임지는 것. 관제탑은 비행기를 몰지 않는다.
- **패턴 5** (그림 5장)
  | 패턴 | 우리말 | 모양 | 고르는 질문 | 공항 |
  |---|---|---|---|---|
  | 순차 | **줄** | A→B→C | 앞 결과가 있어야 다음이 되나? | 활주로 순서 |
  | 병렬 | **나눔** | 동시에 → 합침 | 서로 안 기다려도 되나? | 동시 이착륙 |
  | 계층 | **감독** | 맡기고 결과만 | 과정을 볼 필요 없나? | 관제탑 ↔ 조종사 |
  | 평가 루프 | **되돌림** | 만드는 쪽 ≠ 보는 쪽, 통과할 때까지 | 통과 기준이 있나? | 점검 → 재점검 |
  | 분기 | **갈림** | 조건에 따라 다른 길 | 결과에 따라 다음이 달라지나? | 기상 따라 경로 변경 |
  섞어 쓴다 — 줄 안에 되돌림, 감독 아래 나눔, 갈림 뒤 줄.
- **계약 3칸**(비행계획서): 단계마다 **받는 것 · 내는 것 · 완료 조건**. 내는 것은 양식이 정해져 있어야 다음 일꾼이 읽는다. 완료 조건이 없으면 "됐다"를 모른다.
- **상태와 기억**: 상태 = 어디까지 됐나(관제탑이 든다). 기억 = 일꾼이 알아야 할 것. **일꾼끼리 머리를 공유하지 않는다** — 작업대의 일꾼은 내 대화를 모른다. 그래서 넘길 것을 **문장이나 파일로 명시**한다. 손들기 Q4 "일꾼이 내 대화를 알까요?"(모른다).
- **실패 설계 4**: 재시도(몇 번, 뭘 바꿔서) · 되돌리기(앞 단계로) · 멈춤(사람에게) · 부분 성공(된 것만 내고 안 된 것 표시). 실패 각본은 **미리** 쓴다 — 회항 절차는 이륙 전에 정해져 있다.
- **종료 조건과 예산**: 루프 상한(몇 바퀴) · 비용 상한 · 시간 상한. 없으면 돈이 돈다.
- **사람 관문 3**: 돈 나가기 전 · 밖으로 나가기 전 · 되돌릴 수 없기 전. 예약어 "사람 확인 후".
- **기록과 관찰**(블랙박스): runs/에 **누가 받았고 · 뭘 받았고 · 뭘 냈고 · 어디서 멈췄나**. 기록이 있어야 엇나간 지점을 찾고 표의 한 줄을 고친다.
- **얇은 관제탑**: 순서·상태·호출만. 판단은 일꾼이, 규칙은 지침이. 두꺼워지는 경로 = 예외를 관제탑에 계속 덧붙임 → 일꾼 지침이나 분류표로 내려보낸다.
- **안티패턴 4**: 두꺼운 관제탑 / 숨은 상태(파일에 안 남기고 머릿속에) / 끝없는 루프 / 전부 줄(안 기다려도 될 일을 기다림).
- 손들기 Q5 "내 일은 어느 모양?" (손 5갈래) · 생각 멈춤 ③ "내 일에서 사람이 꼭 봐야 할 자리 하나".

## 6. 실습 설계 — 설계도 4장을 쓰고, 올리고, 돌리고, 고친다 (110분, 개인)

### 6-1. 설계도 4장 서식 (02 템플릿 — 이 서식 그대로)

**① 접수 분류표**
```
[종류 1] ○○ 요청
  정의: ○○를 해 달라는 것
  포함: …, …
  제외: … (→ 종류 2) / … (→ 기타)
  예시: "…" / "…"
  → 담당: △△ 일꾼
[종류 2] …
[기타] 위 어디에도 맞지 않으면 → 사람 (runs/에 "사람 확인 필요"로 남기고 멈춘다)
[섞임] 두 종류에 걸치면 → 쪼개서 둘 다. 순서는 지휘 대본 S-n
[가드레일] 들어오면 거절하는 것: …
```

**② 일꾼 카드** (일꾼 한 명당 한 장)
```
이름: △△ 일꾼
맡는 일(한 줄): …
받는 것: …
내는 것(양식): 제목 / 본문 / 확신도(상·중·하) / 미처리 사항
완료 조건: …
내 일 아님: …이면 "재라우팅 요청"으로 돌려보낸다
```

**③ 지휘 대본** — 번호 문장. 예약어 셋: **동시에** · **통과할 때까지** · **사람 확인 후**
```
S-1 (종류 1): △△ 일꾼에게 요청 원문을 넘긴다 → 내는 것이 양식대로 나오면 끝, 아니면 F-1
S-2 (종류 2): …
S-3 (섞임 1+2): ◇◇ 일꾼 먼저 → 그 결과 파일을 △△ 일꾼에게 → 끝
S-4 (종류 3): □□ 일꾼과 ◇◇ 일꾼에게 동시에 → 둘 다 나오면 합쳐서 끝
S-5 (종류 4): △△ 일꾼이 만들고 → 검토 일꾼이 통과할 때까지 (최대 2바퀴) → 사람 확인 후 끝
관제탑 규칙: 직접 처리하지 않는다 · 한 단계 끝날 때마다 runs/에 한 줄 · 바퀴 상한 3
```

**④ 실패 각본**
```
F-1 내는 것이 양식에 안 맞음 → 같은 일꾼에게 "양식대로 다시" 1회 → 그래도 아니면 F-9
F-2 일꾼이 "내 일 아님" → 접수 분류표로 되돌려 다시 분류 1회 → 그래도 아니면 F-9
F-3 바퀴 상한 도달 → 지금까지 된 것만 내고 "미완" 표시(부분 성공) → F-9
F-9 사람에게 → runs/에 "사람 확인 필요 + 어디서 멈췄나" 남기고 멈춘다
```

### 6-2. 진행 (110분)

| 분 | 단계 | 강사 |
|---|---|---|
| 0–5 | 브리핑 — 서식 4장 · 소재 고르기(A/B/C/자기 업무) · 요청 덱 받기 | 덱은 소재별 12장(정상 8 · 섞임 2 · 기타 2) |

## 7. 완성 예시 한 벌 — 소재 A: 고객 문의 접수 에이전트 (03 배포물 · 모듈 4에서 통독)

**① 접수 분류표**
```
[가드레일] 욕설·협박 · 타인 개인정보 요구 · 우리 서비스와 무관한 요청 → 정중히 거절 문구 1줄, runs/에 "거절" 기록

[종류 1] 안내 요청
  정의: 이미 정해진 규정·절차·정보를 알려 달라는 것
  포함: 환불 절차, 배송 기간, 영업시간, 요금표
  제외: 내 주문 상태(→ 종류 2) / 규정과 다르게 해 달라(→ 종류 3)
  예시: "환불은 어떻게 하나요?" / "배송 며칠 걸려요?"
  → 담당: 안내 일꾼

[종류 2] 조회 요청
  정의: 그 사람의 주문·결제·배송 상태를 확인해 달라는 것
  포함: 주문번호 있는 문의, "내 건 언제 와요"
  제외: 조회 뒤 변경까지 원하면 (→ 종류 3)
  예시: "주문 1234 어디쯤이에요?" / "결제됐는지 확인해 주세요"
  → 담당: 조회 일꾼

[종류 3] 변경·불만 요청
  정의: 주문을 바꾸거나 취소하거나, 불만을 제기하는 것
  포함: 취소, 주소 변경, 환불 요청, 불만, 보상 요구
  제외: 단순 절차 질문(→ 종류 1)
  예시: "취소해 주세요" / "두 번이나 잘못 왔어요"
  → 담당: 변경 일꾼 (사람 확인 후 실행)

[기타] 위 어디에도 맞지 않으면 → 사람. runs/에 "사람 확인 필요 + 원문"
[섞임] 1+2 → S-4 / 2+3 → S-5 / 1+3 → 3 먼저(S-3) 뒤 1
```

**② 일꾼 카드**
```
이름: 안내 일꾼
맡는 일: 규정집에서 해당 항목을 찾아 3문장 이내로 답한다
받는 것: 요청 원문
내는 것: 제목 / 답변(3문장 이내) / 근거 항목명 / 확신도(상·중·하) / 미처리 사항
완료 조건: 근거 항목명이 있다
내 일 아님: 규정집에 없는 내용이면 "재라우팅 요청(기타)"

이름: 조회 일꾼
맡는 일: 주문번호로 상태를 찾아 한 줄로 알려준다
받는 것: 요청 원문 + 주문번호(없으면 되묻기 1회)
내는 것: 제목 / 상태 한 줄 / 조회 시각 / 확신도 / 미처리 사항
완료 조건: 상태 한 줄이 있다
내 일 아님: 주문번호가 두 번 물어도 없으면 "사람 확인 필요"

이름: 변경 일꾼
맡는 일: 변경·취소·환불 처리 초안과 고객 답변 초안을 만든다 (실행은 하지 않는다)
받는 것: 요청 원문 + (있으면) 조회 일꾼 결과 파일
내는 것: 제목 / 처리 초안 / 고객 답변 초안 / 위험 표시(돈·비가역) / 확신도 / 미처리 사항
완료 조건: 위험 표시가 채워져 있다
내 일 아님: 규정 밖 보상 요구 → "사람 확인 필요"

이름: 검토 일꾼
맡는 일: 고객 답변 초안이 규정과 어긋나지 않는지, 약속하면 안 되는 말이 없는지 본다
받는 것: 변경 일꾼의 내는 것
내는 것: 통과 / 수정 요청(이유 1줄)
완료 조건: 통과 또는 수정 요청 중 하나
```

**③ 지휘 대본**
```
관제탑 규칙: 직접 답하지 않는다 · 한 단계 끝날 때마다 runs/<날짜_요청>/에 한 줄(담당·받은 것·낸 것) · 바퀴 상한 2 · 되묻기는 요청당 1회

S-1 (안내): 안내 일꾼 → 내는 것이 양식대로면 끝, 아니면 F-1
S-2 (조회): 조회 일꾼 → 끝 / 주문번호 없으면 되묻기 1회 → 그래도 없으면 F-9
S-3 (변경·불만): 변경 일꾼이 초안 → 검토 일꾼이 통과할 때까지 (최대 2바퀴) → 사람 확인 후 끝
S-4 (안내+조회): 안내 일꾼과 조회 일꾼에게 동시에 → 둘 다 나오면 합쳐서 끝
S-5 (조회+변경): 조회 일꾼 먼저 → 그 결과 파일을 변경 일꾼에게 → S-3 이어서
```

**④ 실패 각본**
```
F-1 양식 불일치 → 같은 일꾼에게 "양식대로 다시" 1회 → 그래도 아니면 F-9
F-2 "내 일 아님" → 분류표로 되돌려 1회 → 그래도 아니면 F-9
F-3 바퀴 상한(2) 도달 → 마지막 초안을 "미검토"로 표시해 F-9
F-9 사람에게 → runs/에 "사람 확인 필요 + 멈춘 단계 + 원문" 남기고 멈춘다
```

**요청 덱 A (12장)** — 정상 8: "환불은 어떻게 하나요" · "배송 며칠 걸려요" · "주문 1234 어디쯤이에요" · "결제됐는지 확인해 주세요" · "취소해 주세요 주문 5678" · "주소 바꿀 수 있나요" · "두 번이나 잘못 왔어요" · "영업시간이요" / 섞임 2: "환불 절차도 알려 주시고 제 주문 9012 상태도요" · "주문 3456 확인하고 취소해 주세요" / 기타 2: "회사 근처 맛집 추천해 주세요" · "담당자 개인 번호 알려 주세요"(가드레일)

> 덱 B(사내 요청 처리 — 증명서·규정·비품·휴가)와 덱 C(콘텐츠 제작 의뢰 — 기획·초안·수정·일정)는 같은 구조로 강사원본에 수록. 정답표(어디로 가야 맞나)도 강사원본에.

## 10. 설계 체크리스트 10 (06 배포물 · 클로징 낭독)

1. 분류표에 **기타**가 있고, 기타의 끝은 **사람**인가
2. 종류끼리 **겹치지 않는가** — 제외 칸이 서로를 가리키는가
3. 종류마다 **예시 문장 2개**가 있는가
4. 일꾼마다 **내는 것의 양식**이 있고, 다음 일꾼이 그 양식을 읽을 수 있는가
5. 일꾼마다 **완료 조건**이 있는가
6. 일꾼마다 **"내 일 아님"**이 있는가
7. 관제탑 대본에 **판단 문장**이 없는가(순서·상태·호출만)
8. **바퀴 상한**과 **되묻기 횟수**가 적혀 있는가
9. **사람 확인 후**가 돈·밖·비가역 앞에 있는가
10. 한 단계마다 **runs/에 한 줄** 남기는 규칙이 있는가

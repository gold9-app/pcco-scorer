# 완성 예시 A — 고객 문의 접수 에이전트 (설계도 4장 + 규정집 + 요청 덱)

> 모듈 4에서 함께 읽고, 모듈 5에서 여러분 설계도의 모델이 되는 한 벌입니다. 베끼는 게 아니라 **서식을 빌리는** 것.
> 소재: 작은 온라인 쇼핑몰의 고객센터. 들어오는 것 = 고객 메시지 한 줄. 나가는 것 = 답변 초안(사람이 보내기 전 확인).

---

## ① 접수 분류표

```
[가드레일] 욕설·협박 · 타인 개인정보 요구(담당자 번호, 다른 고객 주문) · 우리 서비스와 무관한 요청
  → 정중한 거절 문구 1줄, runs/에 "거절 + 사유" 기록

[종류 1] 안내 요청
  정의: 이미 정해진 규정·절차·정보를 알려 달라는 것
  포함: 환불 절차, 교환 절차, 배송 기간, 영업시간, 배송비, 적립금 규정
  제외: 그 사람의 주문·결제 상태(→ 종류 2) / 규정과 다르게 해 달라·불만(→ 종류 3)
  예시: "환불은 어떻게 하나요?" / "배송 며칠 걸려요?"
  → 담당: 안내 일꾼

[종류 2] 조회 요청
  정의: 그 사람의 주문·결제·배송 상태를 확인해 달라는 것
  포함: 주문번호가 있는 상태 문의, "내 건 언제 와요", "결제가 됐나요"
  제외: 확인 뒤 바꾸거나 취소까지 원하면(→ 종류 3) / 일반 배송 기간 질문(→ 종류 1)
  예시: "주문 1234 어디쯤이에요?" / "결제됐는지 확인해 주세요"
  → 담당: 조회 일꾼

[종류 3] 변경·불만 요청
  정의: 주문을 바꾸거나 취소하거나 환불받거나, 불만을 제기하는 것
  포함: 취소, 주소 변경, 옵션 변경, 환불 요청, 잘못 온 상품, 보상 요구
  제외: 단순 절차 질문(→ 종류 1)
  예시: "취소해 주세요" / "두 번이나 잘못 왔어요"
  → 담당: 변경 일꾼 (초안만 — 실행은 사람 확인 후)

[기타] 위 어디에도 맞지 않으면 → 사람. runs/에 "사람 확인 필요 + 원문" 남기고 멈춘다
[섞임] 1+2 → S-4 / 2+3 → S-5 / 1+3 → S-3 먼저, 끝난 뒤 S-1
[되묻기] 조회인데 주문번호가 없으면 "주문번호를 알려 주시겠어요?" 한 번 → 없으면 기타
```

## ② 일꾼 카드

```
이름: 안내 일꾼
맡는 일: 규정집(policy.md)에서 해당 항목을 찾아 3문장 이내로 답한다
받는 것: 요청 원문 + policy.md
내는 것(양식): 제목 / 답변(3문장 이내) / 근거 항목명 / 확신도(상·중·하) / 미처리 사항
완료 조건: 근거 항목명이 있다
내 일 아님: 규정집에 없는 내용이면 "재라우팅 요청(기타)"
```
```
이름: 조회 일꾼
맡는 일: 주문번호로 orders.md에서 상태를 찾아 한 줄로 알려준다
받는 것: 요청 원문 + 주문번호 + orders.md
내는 것(양식): 제목 / 상태 한 줄 / 조회 시각 / 확신도 / 미처리 사항
완료 조건: 상태 한 줄이 있다
내 일 아님: 주문번호가 orders.md에 없으면 "사람 확인 필요(주문 없음)"
```
```
이름: 변경 일꾼
맡는 일: 변경·취소·환불 처리 초안과 고객 답변 초안을 만든다 — 실행은 하지 않는다
받는 것: 요청 원문 + policy.md + (있으면) 조회 일꾼의 내는 것
내는 것(양식): 제목 / 처리 초안 / 고객 답변 초안 / 위험 표시(돈·되돌릴 수 없음) / 확신도 / 미처리 사항
완료 조건: 위험 표시가 채워져 있다
내 일 아님: 규정 밖 보상 요구 → "사람 확인 필요(규정 밖)"
```
```
이름: 검토 일꾼
맡는 일: 고객 답변 초안이 규정과 어긋나지 않는지, 약속하면 안 되는 말(날짜 확정·금액 확정)이 없는지 본다
받는 것: 변경 일꾼의 내는 것 + policy.md
내는 것(양식): 통과 / 수정 요청(이유 1줄)
완료 조건: 둘 중 하나
```

## ③ 지휘 대본

```
관제탑 규칙:
  - 직접 답하지 않는다. 반드시 담당 일꾼에게 보낸다
  - 한 단계 끝날 때마다 runs/<날짜_요청번호>/에 한 줄: 담당 · 받은 것 · 낸 것
  - 바퀴 상한 2 · 되묻기는 요청당 1회

S-1 (안내): 안내 일꾼에게 요청 원문 → 내는 것이 양식대로면 끝, 아니면 F-1
S-2 (조회): 조회 일꾼에게 요청 원문 + 주문번호 → 끝 / 주문번호 없으면 되묻기 1회 → 그래도 없으면 F-9
S-3 (변경·불만): 변경 일꾼이 초안 → 검토 일꾼이 통과할 때까지 (최대 2바퀴) → 사람 확인 후 끝
S-4 (안내+조회): 안내 일꾼과 조회 일꾼에게 동시에 → 둘 다 나오면 합쳐서 끝
S-5 (조회+변경): 조회 일꾼 먼저 → 그 내는 것을 변경 일꾼에게 → S-3 이어서
```

## ④ 실패 각본

```
F-1 양식 불일치 → 같은 일꾼에게 "양식대로 다시" 1회 → 그래도 아니면 F-9
F-2 "내 일 아님" → 분류표로 되돌려 다시 분류 1회 → 그래도 아니면 F-9
F-3 바퀴 상한(2) 도달 → 마지막 초안을 "미검토"로 표시해 F-9
F-4 되묻기에 답 없음 → "주문번호 확인 후 다시 문의 부탁드립니다" 답변 초안 → F-9
F-9 사람에게 → runs/에 "사람 확인 필요 + 멈춘 단계 + 원문" 남기고 멈춘다
```

## 규정집 — policy.md (안내·변경·검토 일꾼이 읽는다, 10항목)

```
1. 환불: 수령 후 7일 이내, 미사용·미개봉. 고객 변심은 왕복 배송비 고객 부담. 환불은 승인 후 3~5 영업일
2. 교환: 수령 후 7일 이내 1회. 불량·오배송은 배송비 회사 부담
3. 배송 기간: 결제 후 1~3 영업일 출고, 출고 후 1~2일 도착 (도서·산간 +2일)
4. 배송비: 3만 원 이상 무료, 미만 3,000원
5. 영업시간: 평일 10:00~18:00, 점심 12:30~13:30, 주말·공휴일 휴무
6. 주문 취소: 출고 전까지 가능. 출고 후엔 수령 뒤 환불 절차로
7. 주소 변경: 출고 전까지 가능. 출고 후엔 택배사에 직접 요청
8. 적립금: 구매액의 1%, 유효기간 1년, 환불 시 회수
9. 오배송·불량: 사진 첨부 시 확인 후 재발송 또는 환불. 추가 보상 없음
10. 약속 금지: 정확한 도착 날짜·시각, 규정 밖 보상·할인은 답변에서 확정하지 않는다
```

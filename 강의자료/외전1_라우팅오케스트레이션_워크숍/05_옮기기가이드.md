# 옮기기 가이드 — 설계도 4장을 작업대(Claude Code)에 올리는 법

> 옮기기는 **복사**입니다. 새로 쓰는 게 아닙니다. 설계도 서식이 그대로 규칙 파일이 됩니다.

## 1. 대응표

| 설계도 | 작업대 파일 | 비고 |
|---|---|---|
| ① 접수 분류표 | `CLAUDE.md` 의 `## 보내는 표` | 가드레일·기타·섞임·되묻기 줄까지 전부 |
| ③ 지휘 대본 + 관제탑 규칙 | `CLAUDE.md` 의 `## 관제탑 규칙` · `## 지휘 대본` | 예약어 셋은 그대로 둔다 — 작업대가 읽는다 |
| ④ 실패 각본 | `CLAUDE.md` 의 `## 실패 각본` | F-9가 마지막 |
| ② 일꾼 카드 | `일꾼/<이름>.md` 한 장씩 | 카드 한 장 = 파일 하나 |
| 요청이 들어오는 곳 | `inbox/` 폴더 | 덱 txt를 여기에 |
| 기록 | `runs/` 폴더 | 작업대가 만든다 — 비워 둔다 |
| 일꾼이 읽을 자료 | `자료/policy.md` 등 | 받는 것에 적힌 파일 |

## 2. 폴더 모양

```
내-에이전트/
  CLAUDE.md          ← ① + ③ + ④ + 관제탑 규칙
  일꾼/
    안내.md          ← ② 카드 한 장
    조회.md
    변경.md
    검토.md
  자료/
    policy.md        ← 일꾼이 읽을 것
  inbox/             ← 요청 txt
  runs/              ← 비워 둔다
```

## 3. CLAUDE.md 뼈대 (이 순서로 붙여 넣는다)

```
# <에이전트 이름> — 관제탑 규칙

## 임무
inbox/ 의 요청을 보내는 표대로 담당 일꾼에게 보내고, 결과를 runs/ 에 남긴다.

## 관제탑 규칙
- 직접 처리하지 않는다. 반드시 담당 일꾼(일꾼/ 폴더의 파일)에게 보낸다. 일꾼을 부를 때는 그 파일의 지침을 그대로 따르게 한다.
- 일꾼에게는 "받는 것"에 적힌 것만 넘긴다. 그 밖의 대화 내용은 넘기지 않는다.
- 한 단계 끝날 때마다 runs/<날짜_요청파일명>/기록.md 에 한 줄: 담당 · 받은 것 · 낸 것
- 바퀴 상한 2 · 되묻기는 요청당 1회 (되묻기는 runs/ 에 "되묻기: <질문>" 으로 남기고 멈춘다)
- "사람 확인 후"가 붙은 단계는 결과를 runs/ 에 "사람 확인 필요" 로 남기고 멈춘다. 실행하지 않는다.

## 보내는 표
(① 접수 분류표 전부 붙여넣기)

## 지휘 대본
(③ S-줄 전부 붙여넣기)

## 실패 각본
(④ F-줄 전부 붙여넣기)
```

## 4. 일꾼 파일 뼈대 — `일꾼/안내.md`

```
# 안내 일꾼

## 맡는 일
규정집(자료/policy.md)에서 해당 항목을 찾아 3문장 이내로 답한다.

## 받는 것
요청 원문 + 자료/policy.md

## 내는 것 (이 양식 그대로)
제목:
답변(3문장 이내):
근거 항목명:
확신도: 상 / 중 / 하
미처리 사항:

## 완료 조건
근거 항목명이 있다.

## 내 일 아님
규정집에 없는 내용이면 답하지 말고 "재라우팅 요청(기타)" 한 줄만 낸다.
```

**작업대 안에서 일꾼을 "진짜 별도 일꾼"으로 돌리고 싶으면** — `일꾼/` 대신 `.claude/agents/<이름>.md` 에 같은 내용을 두고 맨 위에 이름표 네 줄을 붙입니다:

```
---
name: 안내
description: 규정집에서 절차·정보를 찾아 3문장 이내로 답하는 일꾼
---
```

그러면 작업대가 그 일꾼을 **별도 머리**로 부릅니다 — 내 대화를 모르는 진짜 일꾼. 오늘은 `일꾼/` 폴더로 시작해도 됩니다(관제탑이 파일을 읽어 그 지침대로 부른다). 둘의 차이는 "머리를 공유하지 않는다"의 강도입니다.

## 5. 시키는 문장 (둘뿐)

1. **돌리기** — `inbox/ 의 요청을 CLAUDE.md 의 보내는 표와 지휘 대본대로 처리해. 직접 처리하지 말고 담당 일꾼 파일의 지침대로. 결과는 runs/ 에.`
2. **점검** — `runs/ 를 읽고, 보내는 표와 다르게 간 요청이 있으면 어느 줄 때문인지 알려줘. 고치지는 마.`

## 6. 고치기 한 바퀴

엇나간 요청 1건 → 원인은 셋 중 하나: **분류 기준 문장**(정·포·제·예 중 한 칸) / **대본 한 줄**(S-) / **일꾼 카드 한 칸**(받는 것·내 일 아님). 그 **한 줄만** 고치고 그 요청만 다시 돌린다. 기록에 "고친 줄: …"을 남긴다. 코드는 한 줄도 없다.

## 7. 막혔을 때

| 증상 | 원인 | 고치는 줄 |
|---|---|---|
| 관제탑이 직접 답해 버린다 | 규칙이 약함 | 관제탑 규칙 첫 줄을 "직접 처리하지 않는다. 반드시…"로 더 강하게, 일꾼 파일 경로를 명시 |
| 일꾼이 엉뚱한 자료를 본다 | 받는 것에 파일이 없음 | 일꾼 카드 "받는 것"에 파일 경로 |
| 모르는 요청이 아무 일꾼에게 간다 | 기타 줄이 없거나 약함 | [기타] 줄 + "runs/에 남기고 멈춘다" |
| 한 요청이 두 일꾼에게 간다 | 종류가 겹침 | 제외 칸 |
| 끝없이 돈다 | 바퀴 상한 없음 | 관제탑 규칙 "바퀴 상한" |
| runs/에 아무것도 없다 | 기록 규칙 없음 | "한 단계 끝날 때마다 runs/에 한 줄" |
